# CampusRunner 校园跑腿服务平台


## 目标用户

| 角色 | 说明 | 核心需求 |
|---|---|---|
| 学生（发单方） | 有跑腿需求的学生 | 发布任务、支付赏金、查看进度、确认完成、评价 |
| 跑腿员（接单方） | 愿意接单赚取赏金的学生 | 浏览任务、抢单、上传完成凭证、查看收益 |
| 平台管理员 | 平台运营与管理人员 | 用户管理、任务审核、纠纷处理、数据统计 |

## 优先实现的业务场景

优先实现“学生发布代取快递任务，跑腿员抢单，完成后发单方确认并支付赏金”的主链路：

1. 学生发布跑腿任务，填写任务类型、描述、赏金、取件地点、送达地点和期望完成时间。
2. 系统冻结学生支付的赏金。
3. 跑腿员在任务大厅浏览任务并抢单。
4. 跑腿员完成任务并上传凭证。
5. 学生确认完成。
6. 系统解冻赏金并支付给跑腿员。
7. 双方进行评价，更新信用分。

## 两个核心模型

### 1. Task（跑腿任务）

- 描述：发单方发布的一条跑腿需求。
- 关键属性：任务 ID、标题、描述、任务类型、赏金、期望完成时间、取件地点、送达地点、状态、发布者 ID、接单者 ID、创建时间、更新时间。
- 状态规划：待接单、已接单、进行中、待确认、已完成、已取消、已超时。

### 2. Order（任务订单）

- 描述：跑腿员抢单后生成的履约与支付订单，用于记录任务执行和资金流转。
- 关键属性：订单 ID、任务 ID、发单方 ID、跑腿员 ID、订单金额、支付状态、订单状态、创建时间、完成时间。
- 状态规划：待支付、已冻结、已支付、已退款、已关闭。

> 说明：User（用户）是基础角色模型，后续实现时补充
