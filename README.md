## 项目概要

项目名称：CampusRunner
项目简介：一个可以帮助大学生与跑腿员进行交易以及帮助有需要的人兼职跑腿员的平台

业务背景：大学生经常需要代取快递、代买饭、代送文件，但缺少统一、可信的平台。
实际问题：信息分散在微信群，接单效率低、无支付保障、无信用评价

目标用户：学生
用户需求：
    发单：发布任务、支付、查看进度；
    接单：接收任务、收款、上传进度；
    管理：审核、处理纠纷、数据统计

## 项目功能

项目目标：
- 完成校园跑腿最小业务闭环：注册登录 → 发布任务 → 抢单 → 创建订单 → 模拟支付 → 完成确认。
- 完成微服务拆分：用户、任务、订单、支付、通知 5 个服务 + API 网关。
- 完成服务治理：Nacos、Gateway、OpenFeign、LoadBalancer、Resilience4j。
- 完成分布式能力：RabbitMQ/Kafka、Seata/本地消息表、Redis 分布式锁。
- 完成可观测与部署：Zipkin、Prometheus、Grafana、Docker Compose。

适用场景：
    校园内代取快递、代买餐食、代送物品、代还图书等。快递集中到达、天气恶劣、课程冲突、考试周等学生不便亲自处理事务的场景。校园内小团队或学生组织内部的互助跑腿场景。

主要用户角色及需求：
| 角色 | 说明 | 主要需求 |
|---|---|---|
| 学生（发单方） | 有跑腿需求的学生 | 发布任务、支付、查看进度、确认完成、评价 |
| 跑腿员（接单方） | 愿意接单赚赏金的学生 | 浏览任务、抢单、上传凭证、查看收益 |
| 平台管理员 | 平台运营与管理人员 | 用户管理、任务审核、纠纷处理、数据统计 |

功能模块划分：
- 用户模块
    - 注册、登录、退出、校园认证（模拟）、个人信息管理、角色切换（发单/接单）、联系方式管理、信用分查询、收货/送达地址管理
- 任务模块
    - 发布任务、任务分类、设置赏金、任务大厅、搜索与筛选、任务详情、抢单/接单、任务状态流转、上传完成凭证、取消任务、任务超时处理
- 订单模块
    - 订单创建、订单状态管理、订单查询、订单详情、超时未支付取消、超时未确认自动确认、取消/退款记录、纠纷记录
- 支付模块
    - 模拟支付、模拟钱包、支付冻结、支付解冻、退款、交易流水、收益查询、提现（模拟）
- 通知模块
    - 站内信、任务状态变更通知、抢单通知、支付结果通知、超时提醒、系统公告、评价提醒
- 评价模块
    - 双向评价、评分、文字评价、评价列表、信用分计算、举报与申诉
- 管理模块
    - 用户管理、任务审核、分类管理、纠纷处理、数据统计、公告管理、信用体系管理、运营报表

当前项目范围：
校园内跑腿任务发布、抢单、订单状态流转。
模拟支付：支付冻结、解冻、退款、交易流水。
站内通知：任务状态变更、抢单、支付结果、超时提醒。
双向评价与信用分计算。
管理员后台：用户管理、任务审核、纠纷处理、数据统计。
本地 Docker Compose 一键启动全部服务。
基础环境：JDK、Maven、Git、Docker、VS Code + WSL。

暂不实现内容：
真实第三方支付对接（微信/支付宝）。
真实短信、邮件、推送通知。
真实地图导航、定位、骑手轨迹。
跨校服务、多校区复杂调度。
复杂推荐算法、智能定价、风控模型。
高并发、海量数据下的性能优化。
Kubernetes 生产级集群部署。

后续可扩展方向：
